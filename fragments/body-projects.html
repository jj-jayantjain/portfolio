American University · 2025–2026

CommonSpot → Adobe EDS Migration

Team Lead, 4 devs

End-to-end migration of the university's website from CommonSpot CMS to Adobe Edge Delivery Services.

Adobe EDSJavaScriptAEMGit

Business objective

Replace an aging CommonSpot CMS with Adobe Edge Delivery Services to modernize content architecture, improve page performance, and give editorial teams a faster publishing workflow.

Architecture overview

Content authored in a document-based source (Google Docs/SharePoint) compiled into static, edge-cached HTML via EDS's block pipeline — with reusable, independently-versioned blocks replacing CommonSpot's monolithic templates.

Responsibilities

  • Led a cross-functional team of 4 developers — code reviews, sprint/task planning, deployment coordination.
  • Designed and built reusable static and dynamic EDS blocks for consistent page assembly.
  • Integrated required third-party services while keeping delivery secure and on-schedule.
  • Partnered with business stakeholders to translate requirements into scalable EDS solutions.

Challenge

Migrating years of accumulated CommonSpot templates and editorial habits without disrupting an active publishing calendar, across a distributed university content team.

Solution

A phased, block-by-block migration strategy: build and validate each reusable block in isolation, run both systems in parallel per section, and cut over section-by-section rather than in one release.

Business impact

Faster page loads, a simpler editorial workflow, and a component library the university's own team can extend after handover — all delivered by a team of 4 under my technical leadership.

Credera Internal · 2025

GenAI Workflow Automation with OpenAI

OpenAI API

Adobe Workfront Fusion wired to the OpenAI API for event-driven, end-to-end workflow automation.

Workfront FusionOpenAI APIREST/JSON

Business objective

Remove manual handling from a recurring request-and-response workflow inside Adobe Workfront by generating contextual AI responses automatically from structured form input.

Architecture overview

Custom Workfront forms trigger Fusion scenarios via Watch Events; Fusion reads the record, transforms it to JSON, calls the OpenAI API with a curated prompt template, then writes the generated response back into Workfront custom fields — a closed request-to-response loop.

Responsibilities

  • Designed and configured Adobe Workfront custom forms for Projects and Requests.
  • Built Fusion scenarios using Watch Events, Read Record, HTTP, Parse/Transform/Create JSON and Update Record modules.
  • Engineered the GenAI integration layer between Fusion and the OpenAI API.
  • Built filters, error-handling routes and execution logic for fault-tolerant, production-grade automation.

Challenge

LLM responses needed to be reliable enough for a production workflow — handling malformed API responses, rate limits, and edge cases without silently failing a request.

Solution

A layered error-handling design in Fusion: dedicated error routes per module, JSON schema validation before writing back to Workfront, and prompt templates curated per request type to keep output format consistent.

Business impact

A fully automated, event-driven request-to-response cycle — cutting manual turnaround time and giving the team a reusable pattern for future GenAI-in-workflow projects.

Credera Internal · 2022

Internal Accelerator — AEM Solr Connector

Search infrastructure

Enhanced AEM-Solr connector core features: indexing, query boosting, and facets.

AEM 6.5Apache SolrJUnit

Business objective

Improve the internal AEM-Solr search connector used across client accelerators — faster indexing, more relevant results, and broader Solr deployment support.

Architecture overview

A connector layer between AEM's content repository and Apache Solr, handling collection indexing, query boosting, and facet generation, compatible with both Solr standalone and Solr Cloud deployments.

Responsibilities

  • Enhanced core connector features: collection indexing and query boosting integrated with AEM.
  • Developed content page auto-indexing, facets, and featured-results tooling.
  • Improved JUnit coverage and code quality, and validated Solr standalone/Cloud compatibility.

Challenge

The connector needed to behave consistently whether a client ran Solr standalone or Solr Cloud — two deployment modes with different indexing behavior.

Solution

Abstracted the indexing and query-boosting logic behind a compatibility layer, tested against both deployment modes, with an expanded JUnit suite to catch regressions early.

Business impact

A more reliable, reusable search accelerator for future AEM engagements — reducing the setup cost of adding faceted search to new client builds.

Apple Incorporation · 2016–2017

RCM — Migration & Code Optimization

AEM 6.1 → 6.3

AEM version migration with code optimization and OSGi annotation modernization.

AEM 6.3JDK 8Eclipse IDE

Business objective

Migrate the RCM platform from AEM 6.1 to AEM 6.3 while optimizing existing code and removing deprecated patterns.

Architecture overview

Component and template layer modernized from legacy SCR annotations to OSGi annotations as part of the version upgrade, aligning the codebase with AEM 6.3's supported patterns.

Responsibilities

  • Developed and customized various AEM components against evolving requirements.
  • Migrated the platform from AEM 6.1 to AEM 6.3, with code optimization along the way.
  • Enhanced templates and components while migrating from SCR to OSGi annotations.

Challenge

Years of accumulated SCR-annotation components needed to move to OSGi without breaking existing page functionality mid-migration.

Solution

A component-by-component migration and regression-testing pass, validating each converted component against its pre-migration behavior before moving to the next.

Business impact

A modernized, more maintainable codebase on a supported AEM version — my first engagement, and the foundation the rest of this career was built on.
